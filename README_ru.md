# Toropyga\JWT

PHP-класс для создания, проверки и управления JSON Web Token (JWT), включая опциональное хранение в куки браузера.

![License](https://img.shields.io/badge/license-MIT-brightgreen.svg)
![Version](https://img.shields.io/badge/version-v2.1.1-blue.svg)
![PHP](https://img.shields.io/badge/php-v7_--_v8-blueviolet.svg)

- **Пространство имён:** `Toropyga`
- **Класс:** `JWT`
- **Версия:** 2.1.1
- **Зависимости:** `Toropyga\Base` (используется для конвертации массив/объект и метода `getKeyHash()`)
- **PHP:** 7.x / 8.x

> Этот README описывает защищённую версию класса: неподписанные токены отклоняются, алгоритм подписи проверяется по белому списку, а чувствительные данные (токены, payload) никогда не пишутся в логи, даже в debug-режиме.

## Возможности

- Создание и проверка JWT, подписанных через HMAC (`HS256`, `HS384`, `HS512`).
- Строгий whitelist алгоритмов — значение `alg` из заголовка токена должно совпадать с одним из поддерживаемых алгоритмов, что предотвращает атаки типа algorithm confusion.
- Никаких неподписанных токенов — и создание, и проверка токена требуют непустого секретного ключа.
- Проверка стандартных claim'ов при декодировании: `nbf`, `iat`, `exp`.
- Вспомогательные методы для сохранения/чтения/удаления JWT в HTTP-only куки с политикой SameSite.
- `getJWTData()` — для получения заголовка/payload токена без проверки подписи (например, для логирования или определения клиента, чей токен был отклонён/скомпрометирован).
- Внутреннее debug-логирование (`getLogs()`), при этом сырые токены и содержимое payload намеренно исключены из вывода логов.

## Установка

Разместите класс в вашем пространстве имён `Toropyga` (например, через автозагрузку Composer PSR-4) вместе со вспомогательным классом `Toropyga\Base`, от которого он зависит.

    }

## Быстрый старт

```php
use Toropyga\JWT;

$jwt = new JWT();

$secret = 'a-long-random-secret-key'; // храните в конфигурации/env приложения, никогда не хардкодьте в реальных проектах

// 1. Создание токена
$header = ['alg' => 'HS256', 'typ' => 'JWT'];
$payload = [
    'iss'       => 'https://example.com',
    'sub'       => 'user-123',
    'exp'       => time() + 3600,
    'user_id'   => 123,
    'user_name' => 'John Doe',
];

$token = $jwt->createJWT($header, $payload, $secret);
// $token === false при ошибке валидации (см. раздел "Обработка ошибок" ниже)

header('Authorization: Bearer ' . $token);

// 2. Проверка и декодирование токена
$data = $jwt->decodeJWT($token, $secret);

if (isset($data->error) && $data->error) {
    // токен невалиден / истёк / подделан
    echo $data->info; // человекочитаемая причина
} else {
    echo $data->user_name; // "John Doe"
}
```

## Конструктор

```php
public function __construct($server_name = '')
```

| Параметр | Тип | Описание |
|---|---|---|
| `$server_name` | `string` | Опционально. Имя сервера, используемое для определения домена куки. Если не передано, берётся `$_SERVER['SERVER_NAME']`. **Рекомендуется** всегда передавать это значение явно из конфигурации приложения, а не полагаться на заголовок `Host`, который может контролироваться клиентом при некорректно настроенном сервере. |

Конструктор также запускает PHP-сессию (`session_start()`), если она ещё не активна, поскольку некоторые вспомогательные методы (например, длительность сессии "запомнить меня") зависят от `$_SESSION`.

```php
$jwt = new JWT('example.com');
```

## Публичное API

### `createJWT(array $header, array $user_data, string $security): string|false`

Формирует и подписывает JWT.

| Параметр | Описание |
|---|---|
| `$header` | Должен содержать `alg` (один из `HS256`, `HS384`, `HS512`). Опционально: `typ`, `cty`. |
| `$user_data` | Claim'ы / payload. Опциональные стандартные claim'ы: `iss`, `sub`, `aud`, `exp`, `nbf`, `jti`, а также любые пользовательские поля. |
| `$security` | Секретный ключ для HMAC-подписи. **Обязателен** — должен быть непустой строкой. |

Возвращает строку подписанного JWT либо `false`, если:
- отсутствует обязательный ключ заголовка,
- payload пустой,
- `alg` не входит в разрешённый список,
- `$security` пустой.

Точную причину при `false` можно узнать через `getLogs()`.

```php
$token = $jwt->createJWT(
    ['alg' => 'HS256', 'typ' => 'JWT'],
    ['iss' => 'https://example.com', 'exp' => time() + 3600, 'jti' => 1, 'user_id' => 1],
    'security_key_99'
);
```

### `decodeJWT(string $jwt, string $security, ?int $timestamp = null, int $leeway = 0): object`

Проверяет структуру, подпись и стандартные временные claim'ы JWT, затем возвращает его payload.

| Параметр | Описание |
|---|---|
| `$jwt` | Строка JWT. |
| `$security` | Секретный ключ для проверки HMAC-подписи. **Обязателен**. |
| `$timestamp` | Опционально: фиксированное "текущее время" для проверки (Unix timestamp). По умолчанию `time()`. |
| `$leeway` | Опционально: допуск в секундах на расхождение часов при проверке `nbf`/`iat`/`exp`. |

**Возвращаемое значение:**
- При успехе: объект `stdClass` с claim'ами токена (например, `$data->user_id`).
- При ошибке: объект `stdClass` вида:
  ```php
  {
      error: true,
      info: "человекочитаемая причина",
      case: "segments|header|payload|signature|alg|security|signature check|nbf|iat|exp"
  }
  ```

Всегда проверяйте `$data->error`, прежде чем доверять возвращённому объекту:

```php
$data = $jwt->decodeJWT($token, $secret);
if (!empty($data->error)) {
    // отклонить запрос — причину см. в $data->info / $data->case
}
```

**Замечания по безопасности:**
- Значение `alg` из заголовка токена проверяется по внутреннему whitelist'у (`HS256`, `HS384`, `HS512`), прежде чем использоваться для выбора алгоритма хэширования — токен не может заставить сервер использовать неожиданный или небезопасный алгоритм.
- Пустой ключ `$security` отклоняется сразу; подпись никогда не проверяется против пустого секрета.

### `checkJWT(string $jwt, string $security = '', ?int $timestamp = null, int $leeway = 0): object`

Тонкая обёртка над `decodeJWT()`. Задумывалась как точка расширения для логики автоматического обновления токена (например, перевыпуск токена при приближении срока истечения) — эта логика на данный момент присутствует в исходном коде только как закомментированная заготовка и **не реализована**. В текущем виде `checkJWT()` ведёт себя идентично `decodeJWT()`.

---

### `getJWTData(string $jwt): array`

Извлекает заголовок и payload JWT **без проверки подписи**. Используйте только для диагностики — например, чтобы определить субъект токена, не прошедшего верификацию — но никогда как замену `decodeJWT()` при принятии решений об авторизации.

Возвращает:
```php
[
    'header'  => [...],  // присутствует, только если заголовок успешно декодирован и содержит непустой "alg"
    'payload' => [...],  // присутствует, только если payload успешно декодирован
]
```
Возвращает пустой массив, если токен некорректен.

> ⚠️ **Никогда не используйте результат `getJWTData()` для аутентификации пользователя или авторизации действия.** Подпись не проверяется, поэтому содержимое может быть подделано.

---

### `setJWT(array|object $data, string $key, array $header = [], string $cookie_name = '', bool $hash = false): string|false`

Создаёт JWT через `createJWT()` и сохраняет его в HTTP-only куки.

| Параметр | Описание |
|---|---|
| `$data` | Payload (массив или объект, внутри конвертируется в массив). |
| `$key` | Секретный ключ. **Обязателен** — должен быть непустой строкой. |
| `$header` | Опционально; по умолчанию `['alg' => 'HS256', 'typ' => 'JWT']`. |
| `$cookie_name` | Опционально; по умолчанию используется внутреннее значение `token_cookie_name` (`'token'`). |
| `$hash` | Если `true`, в куки сохраняется MD5-хэш токена (через `Base::getKeyHash()`) вместо самого токена. |

Если `$data['exp']` не задан, срок действия вычисляется автоматически:
- `session_live_time` (по умолчанию 3600 сек.) для обычной сессии, либо
- `session_live_time_rem` (по умолчанию 2 592 000 сек. / 30 дней), если `$_SESSION['remember']` истинно.

Используемые флаги куки: `secure = true`, `httponly = true`, `samesite = 'lax'` (изменяются только через прямое редактирование свойств класса — публичных сеттеров сейчас нет).

Возвращает сгенерированную строку JWT либо `false`, если `$data` некорректен, `$key` пустой или создание токена не удалось.

```php
$jwt->setJWT(['user_id' => 1, 'user_name' => 'John'], $secret);
```

---

### `clearJWT(string $cookie_name = 'token'): bool`

Удаляет (обнуляет срок действия) куки с токеном, а также несколько устаревших куки, оставленных для обратной совместимости со старыми интеграциями: `refresh_token`, `API`, `API_R`. Возвращает `true`, если куки была найдена и очищена, иначе `false`.

```php
$jwt->clearJWT();
```

---

### `getLogs(): array`

Возвращает внутренние debug-логи, собранные во время последних операций, вместе с именем настроенного лог-файла.

```php
[
    'log'  => [...],   // массив строк лога (пуст, если внутренний флаг $debug выключен)
    'file' => 'jwt.log',
]
```

> Записи в логе намеренно не содержат сырые токены и декодированное содержимое payload/заголовка, чтобы не допустить утечки чувствительных пользовательских данных — фиксируется только статус высокого уровня (например, "token generated, length=123").

## Статические вспомогательные методы

Не требуют состояния, могут вызываться без создания экземпляра класса:

| Метод | Описание |
|---|---|
| `JWT::jsonEncode($input)` | Кодирует массив в JSON (`JSON_FORCE_OBJECT \| JSON_NUMERIC_CHECK \| JSON_UNESCAPED_UNICODE`). |
| `JWT::jsonDecode($input, $assoc = false)` | Декодирует JSON-строку, сохраняя большие числа как строки. |
| `JWT::base64Encode($input)` | Кодирует строку в Base64-URL (без паддинга). |
| `JWT::base64Decode($input)` | Декодирует строку из Base64-URL. При некорректном вводе возвращает `false` — всегда проверяйте результат перед дальнейшим использованием. |
| `JWT::getSignature($input, $key, $alg = 'sha256')` | Вычисляет base64-URL-кодированную HMAC-подпись для `$input`, используя `$key` и указанный алгоритм хэширования. |

## Поддерживаемые алгоритмы

| Значение заголовка `alg` | Используемый алгоритм хэширования |
|---|---|
| `HS256` | `sha256` |
| `HS384` | `sha384` |
| `HS512` | `sha512` |

Любое другое значение в заголовке `alg` токена — включая `none` — отклоняется как при создании, так и при проверке.

## Рекомендации по безопасности

- **Никогда не передавайте секретный ключ**, используемый для подписи, ненадёжным сторонам — любой, у кого есть ключ, может выпускать валидные токены.
- **Всегда проверяйте `$data->error`** после вызова `decodeJWT()` — возвращённый объект сам по себе не является доказательством валидности.
- **Задавайте домен куки явно** через параметр `$server_name` конструктора в продакшене, а не полагайтесь на fallback к `$_SERVER['SERVER_NAME']` по умолчанию.
- **`getJWTData()` — не механизм аутентификации** — он не проверяет подпись.
- Класс не проверяет `iss`/`aud`/`sub` на соответствие ожидаемым значениям при декодировании; если ваше приложение полагается на эти claim'ы для авторизации, проверяйте их явно после вызова `decodeJWT()`.
- Логика автоматического обновления токена, упомянутая в докблоке `checkJWT()`, не реализована (закомментирована в исходном коде) — реализуйте её самостоятельно снаружи или расширьте класс при необходимости.

## Справочник по обработке ошибок

`decodeJWT()` возвращает объект, у которого `case` принимает одно из значений:

| `case` | Значение |
|---|---|
| `first check` | `$jwt` передан как массив вместо строки. |
| `segments` | Токен не содержит ровно 3 сегмента, разделённых точкой. |
| `header` | Сегмент заголовка не является валидным Base64URL/JSON. |
| `payload` | Сегмент payload не является валидным Base64URL/JSON. |
| `signature` | Сегмент подписи не является валидным Base64URL. |
| `alg` | `alg` отсутствует или не входит в список разрешённых алгоритмов. |
| `security` | Не передан секретный ключ для проверки. |
| `signature check` | Подпись не совпадает (токен был подделан или ключ неверен). |
| `nbf` | Токен использован раньше времени "не действителен до". |
| `iat` | Время выпуска токена находится в будущем. |
| `exp` | Срок действия токена истёк. |
